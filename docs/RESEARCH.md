# Что выяснено о роботах и основе библиотеки

## Модель и инструменты

Рабочая цель — классический четырехосевой **DOBOT Magician**. Это соответствует читаемой надписи на основании на третьем фото и внешнему виду всех трех рук. Точную аппаратную ревизию, серийники и прошивки остальных экземпляров по снимкам определить нельзя. Magician Lite, E6, MG400, M1 Pro и CR требуют отдельного подтверждения совместимости; название Dobot само по себе не означает одинаковый протокол. См. [официальную страницу Magician](https://www.dobot-robots.com/products/education/magician.html) и [реестр источников](SOURCES.md).

| Набор пользователя | Что видно / сообщено | Следствие для библиотеки |
| --- | --- | --- |
| Присоска | На фото 1 видны присоска, трубка и внешний пневмоблок | Управление двумя состояниями: включение управления и всасывание; состояние контроллера не доказывает удержание предмета |
| Лазер | На фото 2 головка с вентилятором и лазерной маркировкой | Есть выход включения, а в протоколе — команда CPLE с полем мощности. Мощность модуля по снимку не установлена |
| Перо | Фото 3 | Рисование — траектория и калибровка рабочей плоскости / смещения инструмента |
| Клешня | Пользователь сообщил о наличии | Методы `open()`, `close()` и `release()` управляют схватом. Удержание предмета проверяет оператор |

В заводском наборе заявлен пневматический gripper, но это еще не доказательство типа конкретной клешни пользователя. Программный поворот R не дает произвольную ориентацию шестикоординатного робота: у Magician четыре оси. Числовые пределы в продуктовой спецификации не описывают все коллизии и доступность каждой декартовой точки.

До создания библиотеки отдельный локальный пульт получил по USB версию `4.0.3` через мост `1a86:55d4`. Впоследствии, 18 ноября 2026 года, соединение и движение проверили через сам пакет на классических Magician. Для 3.7.0 записаны точки маршрута по показаниям контроллера. Для 4.0.3 оператор подтвердил два раздельных штриха и рисунок «67» на бумаге. [Условия и наблюдения](HARDWARE.md)

## Выбор реализации

Основной интерфейс построен на бинарном протоколе классического Magician поверх USB serial. Пакет использует Python и pyserial. В официальном Demo 2.3 есть Python 3.5/3.8, DLL и примеры для сверки. В каталоге производителя API 1.2.3 и Communication Protocol 1.1.5 опубликованы отдельно. [Источник каталога](https://www.dobot.cn/service/download-center)

Параметры последовательного соединения — 115200, 8N1. Кадр содержит заголовок `AA AA`, длину, ID, control, параметры и контрольную сумму. Многобайтные числа передаются в little endian. Чтения выполняются сразу, а запись в очередь возвращает 64-битный индекс. Исполнитель сериализует транзакции и различает приём команды и достижение её индекса. У протокола нет общего идентификатора транзакции, поэтому после сбоя библиотека не повторяет движения. [Протокол V1.1.5, разделы 1.1–1.2](https://download.dobot.cc/product-manual/dobot-magician/pdf/en/Dobot-Communication-Protocol-V1.1.5.pdf)

Для повседневных задач пакет предоставляет `Dobot.connect`, методы положения и движения, группы очереди и оснастки. Для рельсы, конвейера, датчиков, ручного обучения, настроек и I/O есть отдельные группы. Именованный доступ к редким командам через `advanced` проверяет параметры по схеме выбранной команды. [Справочник API](API-REFERENCE.md) · [Матрица протокола](CAPABILITIES.md)

## Противоречия, которые нельзя переписывать из PDF вслепую

В спецификации и DobotLink обнаружились расхождения по идентификаторам, длинам и составу полей. [Исходный код DobotLink на закреплённой версии](https://github.com/Dobot-Arm/DobotLink/blob/80c6ad78010721648ad671cc47320604d303f1d9/Plugins/MagicDevicePlugin/Protocol2/DMagicianProtocol.cpp)

| Место V1.1.5 | Таблица PDF | Официальный encoder / decoder | Решение |
| --- | --- | --- | --- |
| DeviceID, 1.3.6 | ID 4, совпадает с DeviceTime | GetDeviceID использует 5 | Реализован GET с ID 5 |
| AutoLeveling, 1.6.3 | ID 30, совпадает с HOMEParams | Set/GetAutoLeveling использует 32 | Кодек использует ID 32 |
| Alarm response, 1.5.1 | В ответе напечатан 11 | GetAlarmsState использует 20 | Кодек использует GET 20 |
| Clear alarms, 1.5.2 | ID 21 | ClearAllAlarmsState использует ID 20, write | Кодек использует SET 20 |
| JOGL / PTPL / EMotor, GET I/O | Есть несоответствия длины структур и пустые параметры запросов | Официальные структуры уточняют длины и адресный байт запросов | Решения по каждой команде приведены в [реестре кодеков](PROTOCOL-IMPLEMENTATION.md) |
| Queue free space | История 2019-05-05 удаляет GetQueuedCmdLeftspace, общий текст все еще советует его | DobotLink содержит ID 247 | Это firmware-dependent расширение, не гарантировать базовому профилю |
| DeviceVersion | Таблица описывает 3 байта | Decoder Magician читает hwVersion из байта 13 | Декодер принимает 3 или 14 байт, сохраняет исходный ответ и отклоняет другие длины |

Официальный decoder дополнительно содержит команды других устройств. Его наличие в общем исходном файле не подтверждает поддержку каждым классическим Magician. Нужны профиль модели, прошивка и собственные проверки.

## Дополнительные режимы и задания

В стандартном режиме библиотека использует PTP, JOG, CP, ARC, очереди, выводы инструментов, рельсу, внешние моторы, PWM и АЦП. Уровень поддержки каждого направления указан в матрице. Для сложных заданий нужно дополнительно учесть оборудование, формат траектории и настройку рабочего пространства. Рисование пером, например, требует обученной точки касания и подъёмов при переходах между штрихами. [Маршруты и перо](MOTION.md) · [Карта команд](CAPABILITIES.md)

Для штатного экструдера производитель описывает режим **3D Printer Firmware** и передачу нарезанного G-code. В старом руководстве показан Repetier-Host. В текущем руководстве библиотеки описаны интерфейс Python, требования к устройству и дополнительный вариант открытия файла в приложении печати. Физический образец с использованием библиотеки пока не проверен. [Руководство производителя V1.2.5, стр. 68](https://download.dobot.cc/product-manual/dobot-magician/pdf/en/dobot-magician-user-manualV1.2.5.pdf) · [Печать из Python](PRINTING.md)

Открыты форматы двух команд (`ptp_po_with_l`, `queue_start_download`), совместимость дополнительных команд с конкретными прошивками и физические испытания периферии. Транспорт для беспроводных модулей и импорт SVG остаются отдельными направлениями разработки. [План](PLAN.md)

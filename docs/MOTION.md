# Движение и маршруты

Движение доступно сразу после подключения. Чтобы запомнить место захвата или касания, сохрани `start = robot.pose()`. Вызов `robot.move_to(start)` вернёт инструмент в XYZ и R этой позы. Для линейного смещения от неё используй `robot.move_by(z=2)`. Пользовательский код получает группу `robot.motion` из того же подключения. [Пример подключения и первого движения](../README.md)

## Основные вызовы

| Метод | Единицы и поведение |
| --- | --- |
| `move_to(x, y, z, r=None, *, path='linear', wait=True, timeout=30)` | XYZ в мм, R в градусах; абсолютная цель |
| `wait_for_pose(target: Point, *, timeout=5, linear_tolerance_mm=0.3, angular_tolerance_deg=0.65)` | Два последовательных наблюдения цели и отсутствие ошибок. Возвращает последнюю `Pose` |
| `move_by(*, x=0, y=0, z=0, r=0, path='linear', wait=True, timeout=30)` | Смещение XYZ/R через относительный режим контроллера |
| `move_joints(j1, j2, j3, j4, *, relative=False, wait=True, timeout=30)` | Абсолютные или относительные углы в градусах |
| `home(*, wait=True, timeout=60)` | Явный homing, `reserved=0` |
| `speed(*, mm_s, mm_s2, deg_s=None, deg_s2=None)` | Номинальные декартовы PTP скорости и ускорения |
| `jump(*, height, z_limit)` | Высота подъёма и абсолютный максимальный Z в мм |
| `arc(via: Point, to: Point, *, wait=True, timeout=30)` | Дуга от текущей позиции через via к to; обе точки имеют XYZ/R |
| `line_to(x, y, z, *, velocity=0, wait=True, timeout=30)` | Абсолютная CP цель XYZ |
| `line_by(*, x=0, y=0, z=0, velocity=0, wait=True, timeout=30)` | Относительная CP цель XYZ |

При `r=None` сначала валидируются все переданные значения, затем выполняются
`synchronize(timeout)`, чтение R и проверка alarms перед отправкой. При `wait=False`
нужно явно передать R: текущая поза может отставать от уже поставленных целей.
Сторонняя программа и параллельные потоки не должны вмешиваться между барьером,
чтением позы и отправкой. Этот составной вызов не является атомарной транзакцией.
Timeout применяется отдельно к барьеру и к записи/ожиданию backend, а не является
единым сроком всего составного вызова.

`path='linear'` — mode 2 (или 7 для `move_by`), `path='joint'` — 1 (или 8).
`move_joints` использует 4, `relative=True` — 6. Относительный `path='jump'`
отклоняется: в простой обёртке нет подтверждённого соответствующего режима.

JUMP требует успешного явного `jump(...)` на этом объекте Motion. Библиотека не
подставляет высоту по умолчанию и не считает чтение неизвестной старой настройки
явной подготовкой. Ошибка отправки новой настройки отзывает локальное разрешение
JUMP. Произвольное изменение параметров через advanced/другую программу не
отслеживается. При смене сессии фасад должен создавать новый Motion.

`speed()` читает `ptp_coordinate_params`, если хотя бы один параметр R не задан,
и сохраняет недостающие `r_velocity` / `r_acceleration`. Если оба заданы, чтения нет.
Заданные значения проверяются до чтения; полученные параметры R — до записи.
`ptp_common_params.velocity_ratio` и `acceleration_ratio` остаются прежними:
фактические PTP скорости зависят также от этих процентов, траектории, ограничений
и прошивки. `speed()` не задаёт суставные, CP или ARC параметры и не обещает
измеренную физическую скорость.

### Все PTP режимы

`PTPMode` — `IntEnum`, а `motion.ptp(mode, x, y, z, r, *, wait=True, timeout=30)`
даёт прямой доступ ко всем десяти значениям, без замены режима на похожий.
Для JUMP modes 0, 3, 9 также требуется `jump(...)`.

| Значение | Имя enum | Интерпретация |
| --- | --- | --- |
| 0 | `JUMP_XYZ` | JUMP, декартова цель |
| 1 | `MOVJ_XYZ` | MOVJ, декартова цель |
| 2 | `MOVL_XYZ` | MOVL, декартова цель |
| 3 | `JUMP_ANGLE` | JUMP, суставная цель |
| 4 | `MOVJ_ANGLE` | MOVJ, суставная цель |
| 5 | `MOVL_ANGLE` | MOVL, суставная цель |
| 6 | `MOVJ_INC` | Приращение суставных углов |
| 7 | `MOVL_INC` | Линейное декартово приращение |
| 8 | `MOVJ_XYZ_INC` | MOVJ, декартово приращение |
| 9 | `JUMP_MOVL_XYZ` | Прямой wire mode; семантика цели требует проверки профиля |

Источник: [Communication Protocol V1.1.5](https://download.dobot.cc/product-manual/dobot-magician/pdf/en/Dobot-Communication-Protocol-V1.1.5.pdf),
Program 17, локальное текстовое извлечение из SOURCES.md. В том же PDF поле
`ptpMode` подписано 0–8, но enum содержит 0–9; комментарии modes 7 и 9 неоднозначны.
Mode 7 в простом API сопоставлен относительному Cartesian linear согласно контракту
проекта. Для mode 9 обёртка сохраняет enum и отправляет явно переданные компоненты,
не выдумывая абсолютное/относительное толкование. Аппаратная проверка отсутствует.

### CP и ARC

CP: Program 24 задаёт mode 0 как относительный, 1 как абсолютный. Команда не
содержит R. Поле `velocity` в базовом V1.1.5 помечено `Reserved`: простой API
отправляет 0 и отклоняет ненулевое значение до IO. Настройка CP выполняется явным
через `robot.advanced.set("cp_params", ...)`. Поля команды описаны в [схеме протокола](PROTOCOL-IMPLEMENTATION.md).
`speed(mm_s=...)` не настраивает CP. Нельзя считать поле `velocity` скоростью
сегмента на основании одного его имени.

Для дуги передай в `robot.motion.arc(via, to)` промежуточную и конечную точки с XYZ и R. Дуга начинается в текущей позе. Выбери точки, доступные для установленной оснастки.

## Ограниченный JOG

```python
# Отдельный короткий шаг по X у уже подключённой руки.
robot.motion.jog("x", 1, duration=0.2)
```

Оси `x/y/z/r` выбирают декартов JOG, `j1/j2/j3/j4` — суставный. Направление строго
целое +1/-1, время строго `0 < duration <= 5` секунд. Перед запуском выполняются
барьер очереди и `ready()`. Пакеты JOG отправляются сразу (`queued=False`).
Команды +/− соответствуют 1/2, 3/4, 5/6, 7/8 из Program 11.

Любая попытка запуска обёрнута в `try/finally`: после host sleep, прерывания или
неопределённого результата записи выполняется отдельная попытка cmd 0. Ошибка
остановки выходит наружу; исходная ошибка при её наличии остаётся в цепочке
исключений. `jog_stop(*, is_joint=False, timeout=30)` отправляет immediate cmd 0
без `ready()`, чтобы alarm не блокировал остановку. Он не очищает очередь,
не является общим stop и не подтверждает физический покой по одному ответу.

Это таймер процесса, не аппаратный watchdog и не точный предел времени движения.
Задержка ответа на запуск, планировщик ОС, остановленный процесс, потеря питания
компьютера или разрыв связи могут увеличить движение или помешать остановке.
`timeout` применяется отдельно к каждой операции IO. Ни фонового бесконечного JOG,
ни автоматического повторного запуска в этом API нет.

## Маршруты пера / явных точек

`Point(x, y, z, r)` всегда содержит R. `Path` неизменяемый; `then(point)` возвращает
новый маршрут. В конструкторе проверяются все точки и копируется iterable.
`Bounds(minimum: Point, maximum: Point)` задаёт включительные границы XYZ/R.

```python
from dobotkit import Bounds, Path, Point

route = Path([Point(180, 0, 90, 0), Point(180, 10, 90, 0)])
route = route.then(Point(190, 10, 90, 0))
bounds = Bounds(Point(150, -30, 80, -90), Point(210, 30, 110, 90))
preview = route.preview(bounds)  # Только CPU, без IO.
assert preview.bounds == Bounds(Point(180, 0, 90, 0), Point(190, 10, 90, 0))
# route.run(motion, bounds=bounds, wait=True, timeout=30)
```

`preview` возвращает `Preview(points, bounds)` с фактическими extrema точек;
у пустого маршрута bounds равен None. Выход любой точки за переданные границы вызывает
ValueError. Достижимость и свободный ход инструмента проверяются отдельно. Подход к первой точке также не покрывается
границами между неизвестной начальной позой и целью.

`run` проверяет options и весь маршрут до первого обращения к Motion, затем
вызывает только линейные `move_to` с явным R. Возвращает tuple исходных handles.
`timeout` — на каждую точку. `wait=False` не ждёт завершения; пользователь должен
дождаться handles через исполнителя. При ошибке дальнейшие точки не отправляются,
повторов/отката/автоматической очистки нет: уже отправленный префикс может
исполняться, а дескрипторы частичного результата не возвращаются из исключения.
Нет скрытых pen up/down, home, включения инструментов, замыкания контура,
сглаживания, SVG/G-code импорта, 3D-печати или планирования CP lookahead.

## Перо на плоском листе

`pen_path(origin, strokes, start=..., lift_mm=3, dry_run=False, bounds=None)`
принимает точку лёгкого касания листа и фактическую начальную позу как `Point` или
`Pose`. Координаты штрихов задаются в мм относительно XY точки касания. Маршрут
сохраняет начальный R, идёт к первому штриху с поднятой ручкой и поднимает её
между штрихами и в конце. `dry_run=True` сдвигает обе рабочие высоты вверх на
`lift_mm`.

```python
from dobotkit import Dobot

strokes = [[(0, 0), (5, 0)], [(0, 2), (5, 2)]]
# До запуска выставь лёгкое касание закреплённого листа.
port = input("Порт руки: ").strip()
with Dobot.connect(port) as robot:
    contact = robot.pose()
    report = robot.pen.draw(strokes, origin=contact, dry_run=True)
    print(report.completed_points, report.checkpoints[-1].actual.z)
```

Для физического пера закрепи лист, выставь лёгкое касание и сохрани эту позу в
`origin`. Заранее выбери подходящую скорость и обеспечь единоличное управление
очередью на время рисунка, в том числе среди потоков программы.

`robot.pen.draw(strokes, *, origin, lift_mm=3, dry_run=False, bounds=None, timeout=30)`
дожидается уже отправленных этим клиентом команд, проверяет отключение управления
и активации лазера, схвата и присоски, читает стартовую позу и строит весь маршрут.
Перед первым движением метод проверяет стартовую позу двумя чтениями. Для каждой
цели он дожидается индекса и двух совпадающих показаний позы. Параметр `timeout`
в секундах применяется отдельно к каждому ожиданию и операции движения. `dry_run=True`
на подключённом роботе выполняет проход в воздухе. Для расчёта без движения используй
`pen_path()`.

`PenReport.start` содержит стартовую позу, `route` — полный план, `checkpoints` —
подтверждённые точки по порядку. Каждая точка содержит цель `target`, наблюдаемую
позу `actual`, индекс квитанции `queue_index` и прочитанный после движения
`observed_queue_index`. Эти показания описывают состояние контроллера. Качество
следа и контакт с бумагой проверяет оператор.

При ошибке контроллера после построения маршрута поймай исходное исключение
`DobotError` и прочитай `exc.pen_report`. По `completed_points` видна длина
подтверждённой части. `unconfirmed_queue_index` содержит известный индекс
незавершённой проверки, если квитанция была получена. Перед построением маршрута
`exc.pen_report` равен `None`. Исключение сохраняет исходные тип и `stage`.
Остановка или очистка очереди во время рисунка прерывает отправку следующих точек.
При ошибке библиотека прекращает подачу точек и оставляет решение об остановке
и очистке очереди владельцу. Движения не повторяются автоматически. Скорость,
TCP, состояние выходов и положение листа задаёт оператор.

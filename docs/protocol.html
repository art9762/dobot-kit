USB-протокол и исполнение

Как версия 0.3.0a2 переводит Python-вызовы в байты Magician и определяет результат. Коды команд и поведение внутренних классов приведены для диагностики и разработки.

Открытие порта

  • 115200 бод, 8 бит данных, без чётности, 1 стоп-бит. Аппаратное и программное управление потоком отключено.
  • RTS и DTR выставляются в False перед открытием. POSIX использует режим exclusive=True. После открытия очищается входной буфер хоста.
  • Конструктор проверяет ответ GetPose с ID 10. Для выбора модели опирайся на маркировку руки и правильный порт. Само чтение позиции проверяет только ответ.
  • Ответы читаются под блокировкой транспорта. Дедлайн одного обмена равен 1 секунде и включает захват блокировки, отправку кадра и приём ответа. Каждое чтение ограничено остатком бюджета и 50 мс.

Формат кадра

AA AA | LENGTH | ID | CONTROL | PARAMS … | CHECKSUM

LENGTH считает байты ID, CONTROL и PARAMS, от 2 до 255. Максимум параметров составляет 253 байта, весь кадр занимает от 6 до 259 байт. CHECKSUM дополняет сумму байтов полезной нагрузки до нуля по модулю 256. Заголовок и длина в эту сумму не входят.

Бит 0 поля CONTROL означает запись. Бит 1 означает постановку записи в очередь. Запросы чтения используют 0x00, немедленные записи 0x01, отложенные записи 0x03. Многобайтовые числа передаются младшим байтом вперёд. Параметры движения и настройки скорости используют float32.

Пример кадра чтения координат. ID 10 в шестнадцатеричном виде равен 0A, контрольная сумма равна F6.

AA AA 02 0A 00 F6

Разборщик принимает части кадра и пропускает мусор перед заголовком. Запрещённые управляющие биты, длина меньше двух и неверная контрольная сумма прерывают обмен. Транспорт также отклоняет данные, уже ожидающие до отправки, лишние кадры в прочитанном ответе и незавершённый хвост после ответа.

Проверка ответа и обрыв связи

Ответ обязан вернуть ID текущей команды. Для GET проверяется CONTROL=0. Немедленная запись требует CONTROL=1 и пустые параметры. Запись в очередь принимает управляющее поле 1 или 3 и ровно восемь байт с индексом. Для GET размер и смысл параметров проверяются потребителем ответа. Для позиции требуются 32 байта и восемь конечных значений, хотя наружу выходят только первые четыре.

Если драйвер записал только часть кадра, транспорт досылает его оставшийся суффикс в пределах того же дедлайна. При ошибке обмена или прерывании порт закрывается, чтобы отложенный ответ не совпал со следующим запросом. Целый кадр повторно не отправляется. О том, какие признаки ошибки видны из приложения, смотри описание исходов.

Последовательность управляющего вызова

Локальное дополнение датчика цвета использует ID 137 (0x89): немедленный SET с CONTROL=1 и тремя uint8 enabled, port, version; GET с CONTROL=0 без параметров возвращает ровно три uint8 R/G/B. Значения порта: GP1=0, GP2=1, GP4=2, GP5=3; поколения: V1=0, V2=1. Публичный API принимает поколение 1/2 и переводит его в проводной флаг 0/1. SET не ожидает индекс и не подтверждает физическое измерение. Он не очищает очередь. Калибровка также не использует очередь. Источники и ограничения совместимости. Следующие шаги относятся к командам с очередью.

  1. Проверяются пользовательские числа. При первом управляющем вызове отправляются 242 и 245. Если в этой сессии уже выполнена успешная явная очистка через stop(), повторной стартовой очистки не будет.
  2. Для move() и home() читается сигнализация. При move() без угла перед постановкой читается текущая координата угла.
  3. Исполнитель считывает текущий индекс 246 как исходный. Затем отправляет SET с битом очереди и обрабатывает ответ с индексом будущего выполнения.
  4. После принятия первой записи отправляется 240. Последующие записи используют уже запущенную очередь. После stop() следующая принятая команда запускает очередь снова.
  5. Ожидание проверяет сигнализацию, затем индекс. Между итерациями опроса выдерживается до 20 мс с учётом остатка бюджета.
  6. Для move() отдельно читаются позиция и сигнализация до получения двух согласующихся последовательных отсчётов. Остальные управляющие методы завершаются по данным об индексе.

Порядок индексов

Индексы сравниваются по модулю 264, чтобы допустить переход через ноль. Подтверждение новой записи должно лежать строго впереди исходного индекса и предыдущей записи этой сессии, на расстоянии меньше 263. Обратный скачок или скачок на половину диапазона и больше неоднозначен. Такая последовательность приводит к ошибке протокола и закрытию сеанса.

Команда считается исполненной по очереди, когда текущий индекс дошёл до индекса из подтверждения или прошёл его вперёд в допустимом диапазоне. Привязка к поколению сессии позволяет завершить ожидание ошибкой, если параллельный вызов остановил очередь или закрыл соединение.

Состояния исполнителя

Исполнитель держит текущее поколение очереди и внутренние квитанции. После подходящего ответа записи создаётся квитанция accepted. Для записи в очередь её индекс сравнивается с телеметрией. При выполнении условия квитанция переходит в completed. Немедленные записи имеют только ACK без индекса. Их исполнение по индексу проверить невозможно.

Внутреннее состояние cancelled отменяет ожидание конкретной квитанции. Состояние invalidated означает, что квитанция потеряла связь с текущей очередью после очистки или закрытия. Эти состояния проверяются тестами исполнителя. Публичные методы Dobot не возвращают квитанции и не предоставляют отдельной отмены ожидания. stop() обращается к самому контроллеру.

Управляющие вызовы одного экземпляра Dobot используют отдельную блокировку высокоуровневого действия. Она охватывает подготовку, отправку и ожидание. stop() её обходит и меняет поколение в исполнителе. Чтения через position() используют общие блокировки отдельных обменов. Другие программы и объекты не должны параллельно менять ту же очередь.

В протоколе также существует обычная приостановка 241. Она присутствует в тестируемом исполнителе. Dobot.stop() всегда использует принудительную остановку 242 и очистку 245. Публичных методов возобновления, прямой записи по ID и выбора режима очереди в версии 0.3.0a2 нет.

Критерий попадания в точку

Для каждой из двух последовательных позиций евклидово расстояние по XYZ от цели должно быть не больше 0,3 мм, а абсолютная разность угла не больше 0,65°. Те же допуски применяются между двумя наблюдениями. Углы сравниваются как сообщённые числа, без приведения по модулю 360°. Показания сигнализации должны быть нулевыми. Одна совпавшая выборка, за которой пришло несовпадение, обнуляет накопленный результат.

Это критерий совпадения показаний контроллера. Измерение точности оборудования выполняется отдельным прибором или наблюдением, подходящим для задачи.

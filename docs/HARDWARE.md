# Проверка на роботе

Тесты подменяют обмен с контроллером. Примеры для руки и аппаратные сценарии ниже запускает оператор, явно выбрав порт.

## Magician 3.7.0 с пассивным пером, 18 ноября 2026

Проверка выполнена через `dobot-kit` на macOS / Apple Silicon.

| Сценарий | Что подтвердил контроллер |
| --- | --- |
| Подключение и чтение | 14-байтный ответ версии 3.7.0, поза и alarms, выключенные выходы, TCP и параметры PTP |
| Подъём на 2 мм | Очередь 15 → 16. Z −27,734 → −25,734 мм. X, Y и R сохранились |
| Два штриха по 2 мм в воздухе | Все 8 целей MOVL подтверждены индексами 27–34 и двумя чтениями позы на каждой точке |
| Завершение | Force-stop и очистка получили ACK. Скорости восстановлены по чтению настроек, список ошибок пуст |

В первом испытании на бумаге оператор выставил кончик в точку касания. Библиотека
получила все 8 индексов и ожидаемые координаты, включая подъёмы на 3 мм. По наблюдению
оператора рука стояла на месте, а индикатор на основании был погашен при подключённом
адаптере. Этот прогон не прошёл физическую проверку. Поза и индекс очереди могут
совпасть с целями даже в отсутствие наблюдаемого движения.
Второй Magician ответил по USB без ошибок. При подключении того же блока питания
его индикатор тоже оставался погашенным. Оператор слышал сигнал запуска и наблюдал
удержание позы после отпускания Unlock. Бумажный прогон MOVL и отдельный подъём CP
дали ожидаемую телеметрию без видимого движения. Штатный запуск и готовность приводов
проверяются по индикатору на основании. [Руководство Dobot, § 2.3 и таблица 4.4](https://download.dobot.cc/product-manual/dobot-magician/pdf/en/dobot-magician-user-guideV1.5.1.pdf)

В первом проходе исходный исполнитель повторял QueueStart (240) перед каждым MOVL.
На второй цели индекс принял ожидаемое значение, а поза осталась у предыдущей цели.
При диагностическом проходе с одним запуском очереди контроллер подтвердил все 8 целей.
После переноса исправления в библиотеку повтор через обычный API дал тот же результат.

Высота для пробного прохода взята из текущей позы, все подтверждённые контроллером
точки были выше неё.

## Magician 4.0.3 с пассивным пером, 18 ноября 2026

У заменившей устройство руки загорелся зелёный индикатор. Оператор выставил
точку лёгкого касания. Через `dobot-kit` выполнен `pen-paper`: две линии
по 5 мм, смещение по Y на 3 мм, подъём между ними и в конце на 3 мм.
Контроллер подтвердил 8 целей MOVL, индексы 2–9. Оператор увидел на бумаге
два отдельных штриха без перемычки. После теста ошибок нет, настройки скорости
восстановлены и считаны обратно.

Следом рука нарисовала «67» по маршруту 40 × 30 мм. Библиотека получила
44 подтверждения позы и исполнения с индексами 10–53. Между цифрами и после
рисунка ручка находилась на 3 мм выше точки касания. Оператор подтвердил, что
обе цифры целиком видны на бумаге.

Размеры указаны по заданной траектории. Качество и точность следов измерительными
инструментами не проверялись. Локальные JSON-отчёты лежат в `.research/`.

## 1. Только чтение

Освободить USB в существующем пульте и выбрать явный порт. Не запускать одновременно
DobotStudio, DobotLink, старый пульт и новый клиент. Для каждого экземпляра записать
модель, прошивку, оснастку и ОС; точную аппаратную ревизию по фото не предполагать.

```sh
dobot ports
dobot status --port /dev/cu.usbserial-...
```

`ports` только перечисляет кандидатов. `status` использует `read_only=True` и отправляет
только GET. Сверить позу и alarms с известным состоянием, закрыть клиент и проверить
возврат управления к пульту. Сохранить отчёт локально без серийников в публичном Git.

## 2. Очередь и ограниченное движение

Проводить отдельно при свободном месте и присутствии человека. Выбрать инструмент,
TCP и небольшое медленное направление; не копировать условные координаты из примеров.
Перед первым сценарием явно решить судьбу команд, оставшихся в контроллере: новый клиент
не очищает их автоматически. Для изолированного испытания использовать явные stop/clear,
затем нужные настройки скорости и один малый шаг.

Проверить отдельно: ACK с индексом, достижение индекса, чтение позы, остановку с очисткой,
отсутствие возобновления старого задания после переподключения. Значения current index
не являются независимым измерением положения. Линейное и суставное движение, JUMP,
дуги и CP требуют отдельных сценариев. Homing выполняется отдельным действием.

Для воспроизведения с пассивным пером на неподвижном основании освободи порт,
закрепи руку и проверь свободный ход от текущей позиции. Команда `lift` поднимает
перо на 2 мм. `pen-air` ведёт два штриха по 2 мм на высоте 2 мм над текущим Z
и поднимается до 4 мм для переходов. Скрипт очищает очередь, временно задаёт
медленные параметры, читает позу в каждой цели и восстанавливает параметры после
подтверждённой остановки.

```sh
python scripts/magician_smoke.py --port /dev/cu.usbserial-... --exercise lift
python scripts/magician_smoke.py --port /dev/cu.usbserial-... --exercise pen-air
```

Для проверки на бумаге убедись, что индикатор на основании зелёный. Закрепи лист,
подведи кончик до лёгкого касания в начале
первого штриха, отпусти Unlock и убери руки. Скрипт берёт текущую позу за точку
касания. Он выполняет два параллельных штриха по 5 мм, сдвинутых по Y на 3 мм.
Между штрихами и в конце поднимает ручку на 3 мм.

```sh
python scripts/magician_smoke.py --port /dev/cu.usbserial-... --exercise pen-paper
```

Проверь на листе два отдельных следа и пустой промежуток. Чтение позы
подтверждает высоту, которую сообщил контроллер. Качество следов видно на бумаге.

## 3. Оснастка и расширения

Каждый инструмент проверяется отдельно. Для присоски и клешни проверить физическое
удержание/отпускание, включая различие open и release. Для пера — смещение и высоту
контакта. Для лазера нужен отдельный подготовленный сценарий; локальное arm не является
аппаратной защитой. При потере связи библиотека не может подтвердить выключение выхода.

Рельса, конвейер, I/O и датчики требуют своей аппаратной конфигурации. Скорость конвейера
в мм/с доступна после измерения steps_per_mm. Наличие функции протокола не доказывает,
что соответствующее расширение установлено.

## Отчёт

Фиксировать версию пакета/коммит, прошивку, оснастку, команды и единицы, ожидаемое поведение,
ответы контроллера, реально наблюдаемый результат и ограничения. Отдельно отмечать
пройденные проверки каждого режима. Непроверенные функции сохраняют статус «офлайн».
Два неоднозначных формата не исследовать отправкой угаданных пакетов; сначала нужны
надёжная документация или запись обмена известного рабочего официального клиента.

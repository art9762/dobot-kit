Совместимость и разработка

Какие устройства и окружения охватывает библиотека, как перенести старый код, где находятся тесты и как собирается выпуск.

Устройства и окружение

КомпонентКонтракт 0.3.0a2
МодельКлассический четырёхосевой DOBOT Magician со стандартным последовательным протоколом. Для Magician Lite, E6 и других семейств нужен их собственный интерфейс.
ПодключениеПоследовательный порт по USB, указанный оператором. Один владелец порта и очереди контроллера.
ОснасткаКоманды для штатной присоски и пневматического схвата. Инструмент устанавливает и проверяет оператор. Библиотека отправляет выходные команды по выбранному методу.
PythonПакет устанавливается с Python 3.11 и новее. Матрица CI проверяет 3.11–3.14 на Ubuntu и 3.12 на Windows и Intel macOS.
Зависимость во время работыpyserial==3.5. Пакет Python и модуль импорта называются соответственно dobot-usb и dobot_usb.
Форматы дистрибутиваУниверсальный wheel py3-none-any и архив исходников .tar.gz. Для доступа к порту используются драйверы операционной системы.

Статус проверки оборудования

В версии 0.3.0a2 проверки выполняются на подменённом последовательном порту. Они проверяют байты команд, обработку ответов, остановку, таймауты и поведение при противоречивой телеметрии. Для этой версии подтверждение на физическом Magician остаётся открытым.

В предыдущей серии на контроллере 3.7.0 наблюдали отчёт о достижении восьми целей в воздухе. На 4.0.3 оператор дополнительно видел штрихи на бумаге. Это результаты прежней реализации и конкретной оснастки. Точность нового кода, фактическое время движения, homing и работа захватов требуют проверки на оборудовании.

CLI, группы низкоуровневых команд, рельса, конвейер, 3D-печать, автоматические маршруты для пера и лазер удалены при переходе на 0.3.0a1. Старые проекты, которым нужны эти возможности, могут закрепить dobot-usb==0.2.0a4 в отдельном окружении.

Документация 0.2.0a4

Устройство исходников

src/dobot_usb/__init__.py и _robot.py
Публичный класс, проверки параметров, синхронные операции и сверка координат после перемещения.
execution.py
Экземпляр очереди на одно соединение, подтверждения и индексы, ожидание, смена поколения при остановке.
transport.py и protocol.py
Настройка последовательного порта, отправка, проверка байтов и разбор ответа.
validation.py и errors.py
Проверка чисел перед обменом и ошибки со сведениями о том, дошла ли команда до контроллера.
tests/
Офлайн-проверки открытого API, исполнения, транспорта и формата кадров. Подмена serial.Serial обязательна для тестов.
docs/
Редактируемые HTML-страницы и общий CSS. GitHub Pages публикует эту папку из main. Сохраняй ссылки на разделы, если меняешь заголовки.

Проверки перед изменением

uv sync --locked
uv run pytest
uv run ruff check .
uv run ruff format --check .
uv run mypy
uv build

При изменении публичного метода проверь вызов через from dobot_usb import Dobot и повтори его в тесте с подменой транспорта. Для записи проверь байты, обычное подтверждение и потерю подтверждения. Для движения отдельно проверяй реакцию на активную сигнализацию, продвижение индекса и совпадение координат.

Для аппаратного отчёта зафиксируй модель и прошивку, оснастку, сделанные вызовы, значения индексов и координат, наблюдение оператора и способ измерения. Удали серийные номера из публичного отчёта.

Выпуски и изменения

Версия в pyproject.toml и uv.lock совпадает с тегом без ведущей v. Wheel и архив исходников собираются из того же коммита, который указывает тег. Workflow publish.yml сверяет SHA-256 файлов GitHub Release и публикует их на PyPI через Trusted Publishing. Статус пакета, сайта и матрицы CI проверяется отдельно.

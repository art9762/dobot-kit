Справочник API

Интерфейс dobot-usb 0.3.0a1 для классического DOBOT Magician по USB. Пакет экспортирует класс Dobot. Его методы работают синхронно. Команды управления возвращают None после подтверждения, описанного ниже для каждой команды.

from dobot_usb import Dobot

with Dobot("COM3") as robot:
    x, y, z, angle = robot.position()
    print(f"X={x:.1f} мм  Y={y:.1f} мм  Z={z:.1f} мм  угол={angle:.1f}°")

Dobot(port)

Dobot(port: str)

port — непустая строка с точным именем последовательного порта. Строка из пробелов считается пустой. Передавайте имя без лишних пробелов, оно передаётся системе как есть. Примеры имён для разных систем ‒ COM3, /dev/cu.usbserial-1420 и /dev/ttyUSB0. Способ узнать свой порт описан в руководстве по установке.

Конструктор открывает указанный порт со скоростью 115200 бод, 8 битами данных, без бита чётности и с одним стоп-битом. Затем выполняет пробное чтение позиции. При успешном ответе возвращается экземпляр Dobot. Это подтверждает обмен координатами в ожидаемом формате. Выбор модели и порта остаётся за оператором. Открытие порта не вызывает движение, поиск исходного положения, очистку очереди или включение оснастки.

ValueError означает, что имя порта пустое или передано значение другого типа. При невозможности открыть порт, отсутствии полного ответа или неверном формате возможны ошибки соединения и протокола. Если пробное чтение завершилось ошибкой, конструктор освобождает порт.

Контекстный менеджер with

В примере выше переменная robot указывает на экземпляр, созданный конструктором. При выходе из блока with вызывается close(), в том числе если внутри блока возникло исключение. Исключение передаётся вызывающему коду. Для остановки движения используйте отдельный вызов stop() при доступной связи.

position()

position() -> tuple[float, float, float, float]

Читает одну выборку координат у контроллера. Возвращает кортеж (x, y, z, angle). Первые три числа задают положение в системе координат робота в миллиметрах. Четвёртое число задаёт угол поворота насадки в градусах.

Чтение доступно до первой команды управления и после stop(). Оно не запускает очередь и не блокируется из-за ошибки принятой ранее команды, пока соединение открыто. Во время движения результат описывает текущую выборку и может отличаться от заданной точки. Телеметрия контроллера пригодна для сверки команд с показаниями прошивки. Для физического измерения требуется внешний способ проверки.

Библиотека ждёт 32 байта с восемью значениями float32. Все восемь должны быть конечными. Остальные четыре значения, углы сочленений, проверяются при разборе ответа и в кортеж не входят. Ошибка разбора этих данных вызывает ProtocolError без автоматического закрытия открытого сеанса. Отдельные ошибки обмена, например несовпадение ответа с запросом, закрывают соединение. После close() чтение вызывает dobot_usb.errors.ConnectionError.

move(x, y, z, angle=None)

move(x: float, y: float, z: float, angle: float | None = None) -> None

Выполняет прямолинейное перемещение к абсолютной точке (x, y, z) в миллиметрах. Если angle задан, он задаёт абсолютный угол насадки в градусах. При пропущенном аргументе или явном None библиотека запрашивает текущий угол перед отправкой команды. Для относительного подъёма программа сначала считывает координаты и прибавляет высоту к z.

robot.move(x, y, z)                # Сохранить текущий угол
robot.move(x, y, z, None)          # То же с явным None
robot.move(x, y, z, 0)             # Задать угол 0°
robot.move(x=x, y=y, z=z, angle=r) # Задать угол из переменной r
robot.move(*saved_pose)            # Передать x, y, z и угол из кортежа

Координаты и переданный угол принимаются как int или float. Значение должно быть конечным и помещаться в формат float32 контроллера. Для bool, строк, бесконечности, NaN и значений вне диапазона возникает ValueError до обмена с роботом. Проверка формата чисел не определяет рабочую зону. Перед запуском проверьте достижимость цели и свободное пространство вдоль всей траектории с установленной насадкой.

  1. Библиотека готовит очередь при необходимости и запрашивает активные ошибки контроллера. При активной ошибке RobotAlarmError с этапом not_sent означает, что запрос перемещения ещё не отправлен. Если текущий угол нужно сохранить, библиотека читает позицию после проверки ошибок.
  2. После приёма команды контроллером библиотека ждёт, пока индекс выполнения достигнет её позиции в очереди. Бюджет отправки и ожидания индекса составляет 30 секунд.
  3. После выполнения по индексу начинается отдельная сверка координат. В течение 5 секунд библиотека ищет два последовательных показания, близких к цели и друг к другу. Для каждой пары разность по XYZ считается как расстояние в пространстве с допуском 0,3 мм. Проверка угла использует абсолютную разность чисел с допуском 0,65°, без пересчёта по окружности. После каждого чтения позиции снова проверяется состояние ошибок, между итерациями предусмотрена пауза до 40 мс.

Если индекс продвинулся, а показания цели не подтвердились, вызов завершается с ExecutionTimeout и этапом accepted. Ошибки связи, формата ответа или контроллера во время сверки также относятся к этапу accepted. Успех означает совпадение телеметрии по указанным критериям. Паспортная точность, свободная траектория и физическое положение требуют самостоятельной проверки.

home()

home() -> None

Просит прошивку выполнить её процедуру поиска исходного положения. Рука может двигаться по траектории, заданной контроллером. Перед вызовом освободите пространство, предписанное для этой процедуры вашим устройством. При активной ошибке контроллера RobotAlarmError возникает до отправки запроса home().

На отправку и ожидание по индексу очереди отводится 60 секунд. Метод завершает ожидание по данным очереди и контролирует активные ошибки. После возврата можно отдельно вызвать position() и прочитать сообщаемые координаты. Автоматическая сверка с ожидаемой точкой предусмотрена только у move(). Привязка исходного положения к конкретным XYZ зависит от устройства и его настроек.

speed(percent)

speed(percent: float) -> None

percent должен быть конечным int или float в диапазоне от 1 до 100 включительно. Например, speed(10) выставляет коэффициенты скорости и ускорения PTP на 10% от базовых параметров контроллера. При расчёте фактических миллиметров в секунду понадобится знать эти параметры и поведение прошивки.

Недопустимые значения, включая 0 и True, приводят к ValueError до обращения к контроллеру. Вызов меняет настройки последующих PTP-перемещений. На отправку и ожидание по индексу отводится 30 секунд. Метод не считывает записанные настройки обратно. Закрытие соединения не отправляет команду сброса коэффициентов. Для остановки движения есть отдельный вызов stop().

Присоска и пневматический схват

Используйте методы для физически установленной оснастки. Каждый вызов выделяет 30 секунд на отправку и ожидание по индексу. Контроллер сообщает о прогрессе очереди. Эти методы не читают датчики оснастки и не определяют, что установлено на руке. Состояние предмета, захват и усилие проверяйте отдельно. При остановке очереди и отключении порта отдельные команды оснастке не отправляются.

Таблица описывает флаги в отправляемом запросе. Подтверждение обработки не сообщает, открылся ли схват или появилось ли разрежение в присоске.

suction_on()

suction_on() -> None

Активирует выход управления присоской. После вызова убедитесь, что предмет удерживается, прежде чем поднимать его.

suction_off()

suction_off() -> None

Отключает выход управления присоской. Если присоска удерживает предмет, сначала опустите его на подходящую поверхность.

gripper_open()

gripper_open() -> None

Оставляет выход управления активным и подаёт команду раскрыть губки. Используйте этот метод для штатного раскрытия схвата.

gripper_close()

gripper_close() -> None

Активирует выход управления и подаёт команду закрыть губки. После закрытия убедитесь, что предмет закреплён, прежде чем продолжать движение.

gripper_off()

gripper_off() -> None

Отключает выход управления схватом. Физическое положение губок после отключения зависит от оснастки. Для подачи команды открытия используйте gripper_open().

stop()

stop() -> None

Отправляет контроллеру принудительную остановку очереди и затем команду очистки ожидающих действий. Метод ждёт подтверждения обеих операций, без отдельного чтения позиции. Он может прервать ожидающий вызов в другом потоке и сбрасывает блокировку дальнейших действий после сбоя принятой команды. Следующая команда управления при необходимости снова запустит очередь. Метод не отправляет команд присоске или схвату и не сбрасывает активные ошибки устройства.

При ошибке остановки или очистки сеанс закрывается. Одна операция могла пройти, пока вторая завершилась ошибкой. Проверьте фактическое состояние руки перед повторным подключением. У закрытого экземпляра вызов приведёт к dobot_usb.errors.ConnectionError. Программная остановка зависит от живого USB-соединения. При непосредственной опасности используйте штатную физическую остановку согласно инструкции к устройству.

close()

close() -> None

Закрывает локальное соединение и освобождает порт. Повторный вызов возвращает None без дополнительных действий. Контроллер не получает команду движения, остановки, очистки очереди или управления оснасткой. Уже принятая команда может продолжить выполняться на контроллере. Для нового подключения создайте новый экземпляр.

Очередь и время выполнения

При первой команде управления в каждом соединении библиотека останавливает и очищает очередь, где могли сохраниться действия предыдущего приложения. Это происходит и перед speed(), и перед командой оснастки. После успешного stop() очередь уже очищена. Откройте порт только в одном приложении, чтобы старая очередь и чужие команды не смешивались с вашими.

При постановке в очередь контроллер возвращает индекс команды. Если очередь ещё не запущена, библиотека запускает её. Затем она читает активные ошибки перед каждой проверкой индекса выполнения. Для move() и home() есть дополнительная проверка ошибок до отправки самой команды. Для настроек скорости и оснастки такая предварительная проверка отсутствует.

ЭтапБюджет времени в 0.3.0a1

Бюджеты относятся к отдельным этапам. Например, подготовка и чтение текущего угла предшествуют 30-секундному бюджету отправки move(). Обмен, начатый до дедлайна, может завершиться чуть позже. Одновременные команды управления в одном экземпляре выполняются последовательно и могут дополнительно ждать друг друга. Параметры тайм-аутов в публичных вызовах отсутствуют.

Ошибки и диагностика

Неверные значения поддерживаемых аргументов приводят к ValueError. Неполный вызов, лишний аргумент или неизвестное имя аргумента дают обычный TypeError Python. Исключения библиотеки находятся в dobot_usb.errors, их общий базовый класс — DobotError. Исключение dobot_usb.errors.ConnectionError определено отдельным классом библиотеки.

ИсключениеКогда возникает
ConnectionErrorПорт не открылся, связь прервалась или был использован закрытый сеанс.
RequestTimeoutОдин обмен с контроллером не завершился вовремя. Транспорт закрывает соединение.
ProtocolErrorОтвет не соответствует запросу, формат данных нарушен или индекс очереди не согласуется с предыдущими показаниями. Ошибка на уровне обмена закрывает соединение.
RobotAlarmErrorДо move() или home(), во время ожидания команды либо при сверке позиции обнаружены активные ошибки контроллера. Поле alarms содержит номера активных битов.
ExecutionTimeoutИстёк срок ожидания операции, выполнения в очереди или подтверждения позиции.
CommandInvalidatedСеанс или очередь изменились, пока вызов ожидал результата. Такое возможно, если другой поток вызвал stop() или close().
DobotErrorПредыдущее принятое действие завершилось ошибкой. Новая команда управления отклонена в текущем сеансе до явной остановки.

Для журнала доступны stage и его псевдоним outcome. Поля command, queue_index и session_id могут содержать номер команды протокола, индекс назначения и идентификатор сеанса соответственно. Каждое из этих полей равно None, если соответствующие сведения недоступны.

  • not_sent — команда, к которой относится ошибка, не отправлена. До ошибки могли пройти подготовительные запросы, включая остановку и очистку старой очереди.
  • sent_unconfirmed — запрос записан в порт, действительного подтверждения нет. При сбое предварительного чтения ошибка может относиться к запросу телеметрии. Смотрите поле command, если оно заполнено.
  • accepted — контроллер подтвердил приём команды. Физический результат ещё нужно установить.
  • unknown — доступных данных недостаточно, чтобы определить этап.

Этот пример выводит тип ошибки, сообщение и диагностические поля. Вызовы внутри with ограничены чтением позиции.

from dobot_usb import Dobot
from dobot_usb.errors import DobotError

try:
    with Dobot("COM3") as robot:
        print(robot.position())
except DobotError as error:
    print(type(error).__name__, error, error.stage, error.command)

Если робот мог принять действие, сначала проверьте положение руки и оснастку. При действующем соединении используйте stop() перед продолжением. Если соединение закрылось, создайте новый экземпляр после проверки робота. Библиотека не повторяет команду записи автоматически. Подробнее о поведении и восстановлении.

Пошаговые примеры собраны в руководстве. Форматы ответов и внутренний порядок исполнения описаны в справочнике протокола, запуск тестов и совместимость в документации для разработчиков.

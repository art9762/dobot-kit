# Устройство пакета

Для обычного управления используйте `Dobot.connect(port)` и методы открытого соединения. Внутри пакета один `CommandExecutor` связывает эти методы с одним USB-портом и одной очередью классического Magician. Печатающая прошивка использует другой протокол. [Python API](API-REFERENCE.md) · [3D-печать](PRINTING.md)

## Путь команды

1. Фасад в `client.py` предоставляет движение, инструменты и периферию. Группы используют интерфейс `Backend` из `interfaces.py`. Например, `robot.gripper.close()` вызывает именованную запись `gripper` с полями `enabled=True` и `active=True`.
2. `CommandBackend` в `backend.py` выбирает запись из `commands.COMMANDS`. Её `CommandSpec` задаёт ID команды, допустимые направления, структуру полей и правила постановки в очередь. Кодек проверяет аргументы и формирует байты параметров до обмена с устройством.
3. `CommandExecutor` сериализует обмен. Для команды очереди он считывает текущий индекс, отправляет команду, сохраняет выданный индекс в квитанции и при необходимости запускает очередь. Следующие команды добавляются к работающей очереди. При `wait=True` исполнитель проверяет ошибки и ждёт достижения индекса.
4. `SerialTransport.request(command, params=b"", *, write=False, queued=False)` выполняет один обмен с ограничением времени. Слой `protocol.py` отвечает за кадрирование, флаги и контрольную сумму. Параметры GET-ответа декодирует выбранный `CommandSpec`. Адресный ответ EIO дополнительно сверяется с адресом запроса.

`Dobot.connect(port, read_only=True)` ограничивает обмен диагностическими GET. Обычное подключение разрешает записи и выполняет только чтения при открытии. После потери связи требуется новое явное подключение. Закрытие освобождает порт. [Контракт транспорта и очереди](EXECUTION.md)

## Исполнение и составные задания

- Для немедленной записи исполнитель получает пустой ACK. При такой записи публичные группы возвращают квитанцию в состоянии `accepted` с `queue_index=None`. При постановке в очередь ACK содержит индекс uint64, а состояние `completed` требует наблюдения нужного индекса.
- `queue.wait()` ждёт ранее принятую очередь этого клиента. Исполнитель сохраняет собственную квитанцию на последнюю команду при получении ACK, даже если клиент отменил ожидание по своей квитанции.
- `motion.sequence()` привязывает последовательность запросов к текущему поколению очереди. Пауза, остановка или очистка прерывает исходную последовательность. Для взаимного исключения независимых производителей команд владельцу нужна синхронизация на уровне программы.
- `Path.run()` валидирует все точки до отправки и выполняет их в рамках последовательности. `pen_path()` рассчитывает абсолютные точки без USB. `robot.pen.draw()` получает фактический старт, проверяет выходы и подтверждает каждую цель по индексу и двум согласующимся показаниям позы.
- При неопределённом результате записи исполнитель сообщает стадию через `DobotError.stage`. Автоматический повтор записи запрещён. При аппаратном испытании наблюдение контроллера и физический результат фиксируются раздельно. [Аппаратный отчёт](HARDWARE.md)

## Разработка и тестирование

Добавляя команду классического протокола, укажите её источник и проверьте эталонные байты, некорректные параметры и ошибки ответа. Обновите [реестр кодеков](PROTOCOL-IMPLEMENTATION.md) и [карту покрытия](CAPABILITIES.md). Новые методы управления должны пользоваться существующими кодеком, исполнителем и владельцем порта.

Обычный `pytest` выполняет проверки на тестовых реализациях serial и контроллера из `tests/`. Они проверяют байты обмена и реакцию клиента на ответы. Запуск примеров на реальном порту выполняет оператор. Локальные команды проверки и результаты по версиям приведены в [отчёте проверок](VALIDATION.md).

# Состояние и план Dobot Kit

Пакет управляет классическим четырёхосевым Magician из Python через указанный оператором USB-порт. Обычное подключение выполняет диагностические чтения. Движение, выбор начальной точки, управление очередью и включение оснастки задаёт программа оператора. [Начало работы](../README.md) · [Справочник API](API-REFERENCE.md)

## Что уже сделано

| Область | Результат |
| --- | --- |
| Стандартный протокол Magician | Из 69 подразделов V1.1.5 для 67 есть кодеки. Реализованы 47 направлений GET и 56 SET. Причины ограничений двух команд приведены в [матрице](CAPABILITIES.md). |
| Состояние и движение | USB через pyserial, чтение идентификаторов, позы, ошибок и состояния инструментов. Абсолютные и относительные перемещения, возврат к сохранённой позе, суставные команды, JOG, CP, ARC, маршруты по точкам и ожидание позы. |
| Очередь | Сессионные квитанции, ожидание ранее принятых команд, пауза, остановка и очистка. Прерывание составного маршрута действует и между точками. [Контракт исполнения](EXECUTION.md) |
| Оснастка | Присоска, пневматический схват, перо с подъёмами между штрихами и лазерный выход. Для каждого инструмента указаны точки обучения, способы чтения состояния и границы аппаратной проверки. [Инструменты](TOOLS.md) |
| Расширения | Цифровой I/O, PWM, АЦП, датчики, рельса, моторы, конвейер с измеренными шагами на мм, ручное обучение, настройки контроллера и параметры Wi-Fi-модуля. [Периферия](PERIPHERALS.md) |
| 3D-печать | Отдельный режим контроллера, работа с нарезанным G-code из Python и дополнительный вариант открытия файла в локальном хосте. Порядок подключения и ограничения приведены в [руководстве по печати](PRINTING.md). |

## Что уже проверено на устройстве

16 ноября 2026 базовые кодеки и интерфейсы предварительной версии 0.2.0a1 прошли программные испытания. 18 ноября через сам пакет проверили чтение состояния, очередь и короткие маршруты на Magician. На версии 3.7.0 контроллер сообщил о подъёме на 2 мм и достижении восьми целей в воздухе. В бумажных попытках с погашенным индикатором оператор наблюдал неподвижную руку при ожидаемых показаниях контроллера.

На Magician 4.0.3 с зелёным индикатором оператор подтвердил два отдельных штриха без перемычки и рисунок «67». Размер 40 × 30 мм относится к заданному маршруту. Испытания проводились по сценарию из аппаратного отчёта. Более поздний программный интерфейс `robot.pen.draw` проверяется в тестах по тем же типам показаний. [Аппаратные испытания](HARDWARE.md) · [Проверки версий пакета](VALIDATION.md)

## Предстоящие проверки

| Область | Критерий |
| --- | --- |
| Движение | На выбранной руке отдельно проверить суставное движение, JUMP, JOG, ARC, CP и homing. Для оценки точности измерить реальное перемещение независимо от телеметрии. |
| Инструменты | Проверить удержание и отпускание предмета присоской и схватом. Для лазерного сценария отдельно зафиксировать состояние выхода и след на образце. Для печати сопоставить ответы прошивки с температурой, подачей материала и полученным образцом. |
| Дополнительное оборудование | С установленной оснасткой проверить рельсу, шаги конвейера на мм, I/O и показания датчиков. Сохранять версию прошивки, конфигурацию и результаты каждого испытания. |
| Два спорных формата | Найти уточнённую спецификацию или запись обмена известного рабочего клиента для `ptp_po_with_l` и `queue_start_download`. Затем добавить кодек и байтовые проверки именно этой версии. |
| Новые возможности | Для UDP, BLE, расширений прошивки и импорта SVG нужны отдельные контракты. Другие семейства Dobot требуют самостоятельных профилей совместимости. |

При изменении публичного API проверять установку wheel в чистое окружение и запуск обычных тестов. При изменении протокола проверять положительные и ошибочные ответы, квитанции и поведение при потере связи. Для аппаратного результата указывать прошивку, инструмент, отправленные действия, показания контроллера и наблюдение оператора. О достигнутой точности судить по измерению.

## Что проверяют тесты

- Кадрирование, фрагментация, шум, checksum, ограничения памяти и размеров, control flags,
  короткие записи, временные сроки, потеря порта, поздние/неожиданные ответы и отсутствие повторов.
- Независимые эталонные байты всех поддержанных направлений протокола, неверные поля,
  переполнение и float32, варианты версии, адресные GET I/O, строки, bool, IP и union CP.
- Квитанции очереди: ACK отдельно от исполнения, uint64 wrap, stale index, конечное ожидание,
  alarms, cancel, clear/close, одновременные stop/submit и отсутствие повторного старта.
- Ошибки подготовки действия имеют `not_sent`; ошибка после ACK не выдается за отсутствие
  отправки. Прерывание в ожидании закрывает сессию и сохраняет сведения о принятом действии.
- Единый стек facade → codec → executor → binary serial transport → simulated controller,
  включая queued ACK без отраженного queued-bit. Это имитация, а не наблюдение прошивки.
- Пример с переносом предмета, ARC/CP, инструменты, I/O, rail, калиброванный конвейер,
  разрешение лазера, инвалидация старых квитанций и предварительная проверка маршрута.

Симулятор — детерминированная модель состояния. Нет кинематики, препятствий, физического
времени, подтверждения захвата/излучения, датчиков контакта или реального движения мотора.
WAIT/TRIG/JOG/моторы в симуляторе только подтверждаются и записываются.
В текущей версии эта модель есть только в тестах. Тесты не означают точность, безопасность рабочей зоны
или совместимость всех оснасток и прошивок.

## Открытые вопросы

- `ptp_po_with_l`: противоречие структуры и длины данных с рельсой и выходами.
- `queue_start_download`: два uint32 в PDF против двух uint8 в официальном коде.
- Все физические режимы требуют испытания на конкретном экземпляре; дополнительные
  команды расширений и транспорты Wi-Fi/BLE остаются отдельными задачами. Для 3D-печати есть [отдельный клиент](PRINTING.md).

## Повторение проверок в рабочей копии

```sh
uv sync --locked
uv run pytest -q
uv run ruff check .
uv run ruff format --check .
uv run mypy
uv build
uv run dobot commands
```

Примеры из `examples/` подключаются к выбранному оператором порту. Для автоматических проверок транспорт подменяется в `tests/`.

Минимальная версия дополнительно проверена в новой временной `.venv`, созданной через
`uv venv --python 3.11.15`. Wheel и pytest установлены через `uv pip install --python ...
--no-cache`, затем весь набор выполнен через Python этой среды с `-I`, из `/tmp`.
Импорт проверен из site-packages, вне исходного `src/`. Временная среда после проверки удалена.
При пересборке wheel с тем же номером версии стоит использовать новую среду и установку
без кеша: повторный `uv run --with` в этой сессии использовал старую сборку из кеша.

Следующий аппаратный шаг описан в [HARDWARE.md](HARDWARE.md).

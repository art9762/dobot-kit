# Датчик цвета классического DOBOT Magician

В Dobot Kit 0.3.0a4 настройка и чтение штатного датчика используют команду **137 (0x89)**. Контракт пакета сверили 20 ноября 2026 года с исходниками DobotLink, SDK Magician и таблицей совместимости производителя. Проводной формат и ограничения совместимости описаны ниже. [Справочник Python API](https://art9762.github.io/dobot-kit/api.html#color) · [USB-протокол библиотеки](https://art9762.github.io/dobot-kit/protocol.html#commands)

## Как пользоваться из Python

| Вызов | Что происходит |
| --- | --- |
| `robot.color_sensor(port="GP2", version=1)` | Включает конфигурацию V1 на GP2. Выбери порт и поколение по установленной оснастке. Аргумент `enabled` по умолчанию равен `True`. |
| `robot.read_color()` | Один запрос возвращает кортеж из трёх целых чисел от 0 до 255 в порядке R, G, B. |
| `robot.watch_color(handler)` | В том же потоке читает RGB и вызывает `handler(rgb)` при первом показании и каждом точном изменении. При `changes_only=False` обработчик получает все показания. |
| `robot.color_sensor(False, port="GP2", version=1)` | Отключает ту же конфигурацию. Чтобы послать отключение, вызови метод до закрытия USB-сеанса. |

Оба аргумента `port` и `version` обязательны и передаются по имени. Настройка сразу отправляется контроллеру. Возврат `None` означает, что контроллер подтвердил приём команды. Чтение и опрос используют уже установленную конфигурацию.

В `watch_color()` параметр `interval` задаёт паузу в секундах после чтения и обработки. По умолчанию это 0,1 секунды, допустимый диапазон от 0,01 до 60. Для выхода обработчик возвращает именно `False`, либо другой поток устанавливает переданный `stop_event` типа `threading.Event`. Если событие уже установлено перед вызовом, опрос сразу завершается. Исключения обработчика и USB передаются вызывающему коду. `robot.stop()` останавливает очередь движений. [Реализация в пакете](https://github.com/art9762/dobot-kit/blob/v0.3.0a4/src/dobot_usb/_robot.py)

## Обмен по USB

В таблице ID и CONTROL приведены в шестнадцатеричном виде. Значения относятся к прямому подключению классического Magician с нулевыми битами маршрутизации. [Кодировщик команды в DobotLink](https://github.com/Dobot-Arm/DobotLink/blob/80c6ad78010721648ad671cc47320604d303f1d9/Plugins/MagicDevicePlugin/Protocol2/DMagicianProtocol.cpp#L5317-L5343)

| Операция | ID | CONTROL | Параметры запроса | Параметры ответа, принимаемые библиотекой |
| --- | --- | --- | --- | --- |
| Включить или отключить | `89` | `01` | Три байта `enabled, port, version` | Пустой ACK |
| Прочитать RGB | `89` | `00` | Пусто | Три беззнаковых байта `r, g, b` |

Бит 0 CONTROL выбирает чтение или запись. Бит 1 задаёт постановку записи в очередь. Обе публичные операции с датчиком используют немедленный обмен. Обработчик DobotLink также распознаёт ответ с восьмибайтовым индексом, однако SDK датчика не предоставляет выбора режима очереди. Поддержку отложенной настройки конкретной прошивкой эти источники не подтверждают. [Декодер RGB в DobotLink](https://github.com/Dobot-Arm/DobotLink/blob/80c6ad78010721648ad671cc47320604d303f1d9/Plugins/MagicDevicePlugin/Protocol2/DMagicianProtocol.cpp#L2136-L2158) · [Объявления в SDK](https://github.com/Dobot-Arm/Magician_ROS/blob/0bb0dc082596ebce4860212b21068a5c2210b096/src/dobot/src/DobotDll_x64/DobotDll.h#L150-L154)

Для кадра `AA AA LEN ID CTRL PARAMS CHECKSUM` длина равна `2 + len(PARAMS)`. Контрольная сумма равна `-(ID + CTRL + sum(PARAMS)) & 0xff`. Следующие примеры рассчитаны по формату кадра. [Формирование кадра в DobotLink](https://github.com/Dobot-Arm/DobotLink/blob/80c6ad78010721648ad671cc47320604d303f1d9/Plugins/MagicDevicePlugin/Protocol2/DP2Packet.cpp#L245-L299)

```text
Включить V2 на GP2     AA AA 05 89 01 01 01 01 73
Отключить V2 на GP2    AA AA 05 89 01 00 01 01 74
Прочитать RGB          AA AA 02 89 00 77
Подтверждение SET      AA AA 02 89 01 76
Ответ RGB              AA AA 05 89 00 RR GG BB CC
                       CC = -(0x89 + RR + GG + BB) & 0xff
```

## Порты и поколения датчика

| Поле | В Python | В параметрах кадра |
| --- | --- | --- |
| Состояние | `True` / `False` | 1 / 0 |
| Разъём | `"GP1"`, `"GP2"`, `"GP4"`, `"GP5"` | 0, 1, 2, 3 соответственно |
| Поколение датчика | `version=1` / `version=2` | 0 / 1 |

Каждое поле занимает один байт. Числа разъёмов на проводе соответствуют порядку перечисления `ColorPort` в SDK. Поколение описывает периферийный модуль. Например, для датчика V1 на Magician V2 производитель указывает GP2, а для датчика V2 на Magician V1 перечисляет GP1, GP2, GP4 и GP5. Конкретная комбинация зависит от модели руки и оснастки. [Перечисление портов в SDK](https://github.com/Dobot-Arm/Magician_ROS/blob/0bb0dc082596ebce4860212b21068a5c2210b096/src/dobot/src/DobotDll_x64/DobotType.h#L441-L446) · [Сравнение V1 и V2, разделы 3.3, 4.1.3 и таблица 4.6](https://www.dobot-robots.com/insights/news/new-update-to-dobot-magician-comparison-between-v1-and-v2.html)

В старом заголовке ROS SDK `SetColorSensor(bool, ColorPort)` принимает два аргумента, в DobotLink на провод записываются три байта. По этим источникам нельзя установить границу версий прошивки или длину пакета старого контроллера. Библиотека использует описанный трёхбайтовый SET однократно. У отдельного датчика Seeed своя команда 213 и иной формат данных. [Объявления старого SDK](https://github.com/Dobot-Arm/Magician_ROS/blob/0bb0dc082596ebce4860212b21068a5c2210b096/src/dobot/src/DobotDll_x64/DobotDll.h#L150-L154) · [Структуры ответов двух датчиков](https://github.com/Dobot-Arm/DobotLink/blob/80c6ad78010721648ad671cc47320604d303f1d9/Plugins/MagicDevicePlugin/Protocol2/DMagicianProtocol.h#L593-L605)

## Что проверено

Автотесты проверяют кодирование команд, длину ответа, порядок RGB и условия выхода из опроса на имитации USB. В аппаратном прогоне библиотеки 0.3.0a2 от 27 ноября 2026 года контроллер классического Magician с прошивкой 4.0.3 принял команды включения и отключения на свободном GP2 с параметром V1. На запросы чтения приходило по три байта, обработчик опроса получил несколько показаний. К разъёму в этом прогоне не подключали датчик.

Для проверки конкретного модуля нужны подключённый датчик и известные образцы. ACK подтверждает обмен с контроллером. Нулевой RGB, повторяющаяся выборка или отдельное изменение сами по себе не устанавливают наличие датчика, свежесть измерения, физический цвет или точность. Источники описывают три 8-битных компонента. Калибровку, задержку измерения и поведение отключённой оснастки нужно оценивать отдельно.
